# 로또방 웹 경험 기획 및 스토리보드

## 제품 목표

- 로또 추천 결과를 콘솔 출력이 아니라 한눈에 읽히는 로컬 웹 대시보드로 재구성한다.
- 추천 번호만 보여주지 않고 최근 과거 1등 번호 흐름과 1등 배출점 맥락까지 함께 보여준다.
- 자동 구매나 과장된 예측 메시지는 배제하고, "분석 참고 후 수동 구매"라는 제품 원칙을 유지한다.

## 정보 구조

1. 히어로
   오늘 기준 추천 실행, 최근 회차 요약, 수동 구매 원칙
2. 생성 컨트롤
   세트 수, 주간 기본 시드, 데이터 파일 경로, 추천 다시 생성 버튼
3. 전략 브리프
   상위 가중치 번호, 최근 분석 회차, 생성 시각, 추천 규칙 요약
4. 당첨 통계
   가장 많이 당첨된 숫자, 출현 횟수, 출현 비율
5. 추천 번호 보드
   5개 티켓 카드, 점수, 번호 컬러칩, 수동 입력용 요약
6. 과거 1등 히스토리
   회차, 추첨일, 1등 번호, 보너스 번호, 1등 당첨자 수, 1인당 당첨금
7. 당첨 판매점 보드
   회차별 1등 배출 지역, 판매점명, 자동/수동 구분, 주소
8. 가이드 풋노트
   구매 자동화 미포함, 공식 정보 출처, 수동 구매 안내

## 비주얼 방향

- 톤: 복권 용지와 전광판의 중간 지점. 종이 질감 위에 강한 레드, 크림, 골드 포인트를 사용한다.
- 레이아웃: 일반 대시보드보다 포스터에 가깝게 구성하고, 큰 숫자와 넓은 여백으로 긴장감을 만든다.
- 타이포그래피: 디스플레이 영역은 압축된 굵은 헤드라인 계열, 본문은 인쇄물 느낌의 세리프 계열을 사용한다.
- 모션: 초기 진입 시 카드가 위에서 아래로 계단식 등장하고, 번호볼은 생성 시 미세하게 튀어오른다.

## 데이터 모델 메모

- 추천 데이터
  - 추천 세트, 세트별 점수, 상위 가중치 번호, 생성 시각, 주간 기본 시드
- 당첨 통계
  - 번호, 출현 횟수, 전체 회차 대비 출현 비율
- 과거 1등 데이터
  - 회차, 추첨일, 당첨번호 6개, 보너스 번호, 1등 당첨자 수, 1인당 당첨금
- 당첨 판매점 데이터
  - 회차, 지역, 판매점명, 자동/수동 여부, 주소

## 스토리보드

### 장면 1. 첫 진입

- 사용자는 진한 레드 배경 위 "로또방" 타이틀과 최신 추천 실행 버튼을 본다.
- 상단 브리프에는 최근 분석 회차와 "수동 구매 전용" 배지가 고정 노출된다.
- 기대 효과는 단순 CLI 도구가 아니라 결과를 설명하는 제품이라는 첫인상을 주는 것이다.

### 장면 2. 추천 생성

- 사용자는 세트 수를 조정하거나 주간 기본 시드를 그대로 사용해 추천을 생성한다.
- 티켓 카드 5장이 순차적으로 등장하고 각 카드에는 번호볼, 평균 점수, 티켓 번호가 표시된다.
- 우측 또는 하단 브리프에는 상위 가중치 번호와 생성 시각이 즉시 갱신된다.

### 장면 3. 전략 읽기와 통계 확인

- 사용자는 "왜 이 번호가 떴는지"를 전략 브리프와 당첨 빈도 통계에서 확인한다.
- 상위 가중치 번호, 최근 회차 기준, 홀짝/합계/연속번호 제약과 함께 많이 당첨된 숫자 순위를 읽을 수 있다.
- 이 장면은 결과에 최소한의 해석 레이어를 제공하는 역할을 한다.

### 장면 4. 과거 1등 히스토리 탐색

- 사용자는 최근 대표 회차의 1등 번호를 가로 타임라인 또는 카드 목록으로 확인한다.
- 각 항목에는 회차, 추첨일, 1등 번호, 보너스 번호, 1등 당첨자 수, 1인당 당첨금이 함께 표시된다.
- 이 장면은 추천 결과와 실제 당첨 이력 사이의 감각적 연결을 만든다.

### 장면 5. 1등 배출점 확인

- 사용자는 회차별 1등 배출점 보드에서 지역 분포와 판매점을 본다.
- 카드에는 지역, 판매점명, 자동/수동 여부, 주소가 표시되고, 같은 회차의 여러 판매점이 묶여 보인다.
- 이 장면은 "번호" 중심 화면에 현실 세계의 장소감을 추가한다.

### 장면 6. 마무리 행동

- 페이지 하단에는 "자동 구매 미포함" 안내와 공식 출처 링크가 배치된다.
- 사용자는 추천 번호를 수동으로 입력하거나, 출력된 텍스트를 보고 직접 구매 여부를 결정한다.
- 제품은 분석 도구에서 멈추고 구매 행위는 사용자 판단에 맡긴다.

## 구현 순서

1. 추천 로직을 재사용하는 로컬 HTTP 서버와 JSON API를 만든다.
2. 주간 기본 시드를 계산하는 규칙과 당첨 빈도 통계를 API payload에 포함한다.
3. 과거 1등 번호 및 1등 배출점용 로컬 데이터 파일을 만든다.
4. 단일 페이지 정적 UI를 추가하고 API 응답을 카드형 레이아웃으로 렌더링한다.
5. README에 웹 실행 경로와 제한 사항을 추가한다.
6. API payload 테스트를 추가해 기존 CLI 기능과 함께 검증한다.

## 출처 메모

- 과거 회차 당첨번호 및 당첨금: 동행복권 `gameResult.do?method=byWin`
- 회차별 1등 배출점 정보: 동행복권 `store.do?method=topStore&pageGubun=L645`
- 실제 운영 시에는 공식 페이지를 정기 수집하거나 수동 갱신하는 보조 스크립트를 두는 편이 안전하다.
